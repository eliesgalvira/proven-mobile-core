# 03 Test vectors into Bend

Depends on: 01.

## Goal

1. Make sure the official vectors are committed as JSON under `test-vectors/spec/`, one file per source. Some may already be on `main`; fetch only the missing ones. Each file has `source` (document, version, section, URL) and a list of cases. Fetch from the primary source only (3gpp.org, ETSI, NIST, rfc-editor.org), never from another implementation. The sources:
   - FIPS 180-4 / NIST CSRC examples (SHA-256: "abc", the 448-bit message);
   - RFC 4231 (HMAC-SHA-256, cases 1 to 7);
   - FIPS 197 Appendix C.1 (AES-128);
   - RFC 4493 (AES-CMAC, examples 1 to 4);
   - NIST SP 800-38A F.5.1 (AES-128-CTR);
   - RFC 7748 §5.2 and §6.1 (X25519);
   - 3GPP TS 35.208 (Milenage test sets 1 to 6);
   - 3GPP TS 33.501 Annex C.4 (SUCI Profile A);
   - 3GPP TS 33.401 Annex C (128-EEA2 and 128-EIA2 test sets).
2. Extend `scripts/gen-vectors.py` to emit `kernel/tests/vectors/<name>.bend` modules exposing each case as Bend data.
3. Generate the modules for `test-vectors/capture/vectors.json` as well.

## Done when

Every JSON file has a `source` field, `kernel/tests/vectors/` is regenerated by `scripts/gen-vectors.py` with no diff, and a smoke test `kernel/tests/vectors_load.bend` prints the count of cases per file and `PASS`.

## Verify

`python3 -I scripts/gen-vectors.py --check && scripts/check.sh`
