# Decisions

The loop adds one line per decision it takes: the decision, the ticket, and why.

## Defaults set before the loop started, reviewed by the owner on 2026-11-03

- NAS ciphering NEA2 then NEA0, integrity NIA2 only: changed. The example config offers NEA2 alone, because every 5G UE supports it (TS 33.501 §5.11.1.1) and NEA0 only leaves room for a downgrade. NIA0 stays unrepresentable.
- No CM-IDLE, no Service Request, no paging: kept for milestone 1, but a UE that comes back with a protected initial message must be told to register again rather than getting Error Indication (ticket 35).
- PDU Session Modification Request always rejected with #31: kept.
- SQN held in memory, AUTS re-synchronisation after a restart: kept.
- The loop writes `kernel/LAWS.bend`: kept. The owner's review found laws weaker than their tickets or stated over functions the kernel never runs (§ Owner review, tickets 32–34).
- NGAP pinned to TS 38.413 V17.15.0, pycrate 0.8.1 and a Python generator: kept. pycrate's version is pinned in a flake dev shell (ticket 37).
- Framed TCP between kernel and edge, entropy from the edge: kept.
- Law conventions of `docs/spec/milestone-1.md`: kept.
- Allow-all permissions: replaced by a narrow allow list (`.claude/settings.json`). The next unattended cloud loop runs in Auto mode.
- Trusted network level, with Bend and Lean installed from GitHub release assets: kept. Lean is needed by `bend --verdict`.

## Taken by the loop

- Ticket 02: a law's "v in range" condition is the mask equation `U32.and(mask, v) == v` (so `U32.and(255, v) == v` for a byte), not `U32.is_lt`. Both say the same thing; the mask form lets the proof rewrite once and compute, while `is_lt` would need a 32-case lemma relating `Word.cmp` to the bits. `is_byte` stays the runtime check.
- Ticket 02: multi-byte values are assembled by bit layout (`cat4`: four bits of one word, then twenty-eight of another) instead of `shl`/`or`. Base's `Bool.or` matches its first argument, so `or` of a symbolic bit with a constant never computes and every roundtrip would need dozens of hand-written rewrites; the layout form reduces to `{==}` after destructuring the U32. No `kernel/u32_lemmas.bend` was needed.
- Ticket 02: proofs live in `kernel/proofs/<area>.bend`, imported by `kernel/PROOF.bend`; `scripts/acceptance.py` looks in both. One file per ticket area keeps PROOF.bend from growing without bound.
- Ticket 03: "every JSON file has a `source` field" is read as every official file under `test-vectors/spec/`. The capture files (`capture/vectors.json`, `eupf-probes.json`, `logs/eupf-sessions.json`) carry their provenance as `description`/`pcapng_sha256` and may not be edited by the loop; the generator still converts them.
- Ticket 07: `kdf.serving_network_name(mcc, mnc)` takes the MCC and MNC as digit lists rather than the 3-byte PLMN encoding, so the KDF module stays independent of the NAS codec (ticket 10 decodes PLMN bytes to digits). A two-digit MNC is written with a leading zero, as the capture shows (`mnc001`).
- Ticket 07: KAMF uses the IMSI digits as the SUPI (TS 33.501 A.7 with the TS 23.003 IMSI form, no `imsi-` prefix) and KgNB the uplink NAS COUNT; both reproduce the captured keys. NAS MAC verification itself waits for NIA2 in ticket 09.
- Ticket 08: fixed-count loops whose result a law talks about (the X25519 ladder and the field inversion) iterate over a list rather than a `Nat` counter, and that list is derived from the symbolic input (the scalar's bits; a match on the base for the inversion). Bend's checker normalises types fully, so a concrete counter unrolls every step and overflows the machine stack (Bend WONTFIX "the checker is not optimal" (#993, #1075)).
- Ticket 08: `suci.deconceal.length_checked` states "the MAC is compared over all 8 bytes" as: a Done answer implies the expected tag equals the received tag as lists, and the expected tag is 8 bytes. `bytes_eq` of two lists reflects to list equality, so a shorter received tag can never compare equal.
- Ticket 08: the routing indicator is one to four digits padded with 1111 (TS 24.501 §9.11.3.4), which plain TBCD rejects; `Routing.read`/`Routing.write` handle it, and `Routing.valid` is the roundtrip's precondition.
- Ticket 08: the PLMN type holds its six nibbles as fields (`mnc3 = 15` for a two-digit MNC) so that an invalid shape is unrepresentable and the wire form is one function of the fields.
- Ticket 09: BEARER is 1 for every NAS message. TS 33.501 §6.4.3.1 sets BEARER to the NAS connection identifier, 0x01 for 3GPP access (0x02 for non-3GPP), and the captured MACs verify with 1.
- Ticket 09: the uplink COUNT estimate (TS 24.501 §4.4.3.1) rejects a sequence number equal to the last accepted one as a replay, treats a smaller one as the next overflow, and refuses to accept once the 16-bit overflow counter would wrap (a fresh authentication is needed). "The COUNT moved forward" (`Nas.Count.advanced`) is stated structurally: same overflow with a larger sequence number, or the next overflow with no wrap.
- Ticket 09: the selected algorithms are closed datatypes (`Nas.Ea` = NEA0 | NEA2, `Nas.Ia` = NIA2, `Nas.Protection` = header types 1-4), so an unsupported algorithm or header type is unrepresentable in a context.
- Ticket 09: CMAC takes a bit length (`cmac_bits`), as RFC 4493 and TS 33.401 Annex B define it, so every 128-EIA2 test set runs; the block loop takes its padding as a template argument.
- Ticket 10: a decoded 5GMM message is `Mm{type, fields, opts}`: the mandatory fields in the order of the message's table (one of three layouts, V1, LV, LV-E) and the optional IEs in wire order with their format, IEI and length bytes as read. One generic codec serves the nineteen message types, so the three message laws are proven once, and typed views (`kernel/nas/ies.bend`, `kernel/nas/mobile_id.bend`) decode the content of each IE separately.
- Ticket 10: an optional IE's format comes from TS 24.007 §11.2.4 (IEI at or above 0x80 is one octet; below, TLV) plus the per-message exceptions of TS 24.501 §8.2 for TV and TLV-E, written as the table `Mm.format`. Lengths stay as the wire word tied to the content by the validity predicate (`fits8`/`fits16` and `Nat.is_eq(to_nat(len), length(body))`), which avoids a `to_nat`-of-`from_nat` lemma.
- Ticket 10: `nas.mm.suffix` and `nas.mobile_identity.suffix` assume `all_bytes(bs)`: a two-byte length or a 24-bit TAC written back from arbitrary 32-bit list elements would not reproduce them. Every real input is a byte string, and `decode_valid` needs no such hypothesis because the readers check `fits8`/`fits16` as they go.
- Ticket 10: `Mm.read` handles plain messages only (security header type 0); protected ones go through `Nas.open` (ticket 09) first. The optional-IE loop takes its fuel from the byte count, as every IE takes at least one byte.
- Ticket 10: the 5GS mobile identity keeps the AMF set identifier and pointer packed in one 16-bit word as on the wire (views `amf_set`/`amf_pointer`); SUCI reuses the ticket 08 `Suci` type (SUPI format IMSI only; a NAI-format SUCI, MAC address or EUI-64 identity is `Unsupported`). IMEI and IMEISV are decoded only with the digit count their type fixes (15 and 16), so the odd/even flag can never disagree with the digits.
- Ticket 10: the TAI list decodes all three partial-list types (00, 01, 10); the capture carries type 10 with one TAI. Typed views of the remaining IEs are wire-faithful (flag bits and packed bytes kept, with accessors) and have tests on every capture message but no laws of their own; the payload container is the LV-E field itself (`I.lve`), which the two `nas.payload_container` laws describe.
- Ticket 11: 5GSM messages reuse the 5GMM machinery: the optional-IE codec is generic over a per-message rule table (`I.Rule{iei, low}`, in `kernel/nas/ie.bend`), so `Mm` and `Sm` share one reader, one writer and one set of proofs. The PDU session identity and PTI are kept as bytes checked with `fits8`.
- Ticket 11: a packet filter component is `Comp{kind, payload}` with the kind byte kept as read and the payload shaped by a table over the component type identifiers of TS 24.501 Table 9.11.4.13.1; an identifier outside the table is `Unsupported`. A mask is contiguous when `not(m) & (not(m) + 1) == 0`, which is the arithmetic form of "ones from the top bit"; the IPv4 reader checks it, so the law follows from the reader alone.
- Ticket 11: QoS rules, packet filters and QoS flow descriptions keep their header bytes and declared lengths as read, with views for the fields they pack (`Rule.code`/`dqr`/`count`, `Filter.direction`/`id`) and `Rule.shape_ok` tying the operation code to the shape of the filters and tail; each body is cut with the declared length (`I.lve`, `I.lv`) before it is decoded, so a length that disagrees with the contents is `Fail`. The `nas.qos_rules.suffix` law assumes `all_bytes(bs)`, as the ticket 10 suffix laws do.
- Ticket 11: Session-AMBR units are valid up to 26 (TS 24.501 Table 9.11.4.14.1 defines 0x00 to 0x1a); the reader takes exactly six bytes and rejects the rest, so `decode_valid` needs no hypothesis.
- Ticket 11: an ePCO is a list of containers with the identifier and the length byte as read; `Epco.valid` carries the three bounds (at most 255 containers, every container's length byte fits and matches its body, total size at most 65534). The unconditional encode bound of the ticket is false (255 containers of 255 bytes encode to 65790 bytes), so `nas.epco.encode_bounded` assumes `Epco.valid`, and since the reader checks the same bounds `decode_bounded` yields full validity. The ePCO reader requires the extension bit (0x80) in the first octet.
- Ticket 12: the APER stream is a list of bits in wire order with a cursor `Cur{rem, bits}`, where `rem` is the number of bits left before the next octet boundary; readers return the value and the cursor after it, writers prepend to `rest` and take the `rem` they start at, and each primitive has an `after(rem)` so writers compose without closures or `++` chains (`A.write(a, rem, B.write(b, A.after(a, rem), rest))`). Bytes enter and leave through `unpack`/`pack`.
- Ticket 12: a constrained whole number in a bit-field is kept as its offset from the lower bound, as on the wire (`Int`, with `diff` the range less one); the generator adds the bound in a view. Its validity is `fits(n, x) ∧ x ≤ diff`, where `fits` says the bits above n are zero; the first conjunct follows from the second when `diff` fits n bits, but proving that monotonicity costs more than carrying it. Ranges of 256 and 257..64K use `AInt` (one or two aligned octets); ranges above 64K use `Big`, whose value is its canonical minimal octets (no leading zero), which also covers AMF-UE-NGAP-ID and BitRate without ever building a `Nat` or a U32 that would overflow.
- Ticket 12: a normally small number is read only in its 7-bit form; the long form (64 and above) is `Unsupported`, since no NGAP type has that many extension additions or alternatives.
- Ticket 12: a length determinant (`Len`) is a `Nat` below 16384; the fragmented forms are `Unsupported`, and a two-octet form holding a value below 128 is `Invalid`, so decoding is canonical. Constrained lengths (`Size`) take the lower bound and `diff`, plus a flag `al` for ranges above 255 whose length is one or two aligned octets (TS 38.413 containers are `SIZE(0..65535)`, two aligned octets); the laws assume `diff < 2^n` of the generator's parameters.
- Ticket 12: `aper.padding_zero` stays strict: every alignment in the fourteen captured UERANSIM and Open5GS PDUs is zero padding (the IE walk test), so no relaxation was needed.
- Ticket 12: a printable character is a byte in the PrintableString alphabet (`is_byte ∧ alphabet`), so printable strings are byte strings by definition rather than by a U32 order lemma. Variable-size bit strings, octet strings and strings align their contents after the length, as X.691 §16.11/§17.7 and the captured TransportLayerAddress show.
- Ticket 12: `Nat`s read from bits go through `Nat.of_lsb`/`Nat.to_lsb` (halving and parity), and U32s through `Word.prefix`/`Word.of_lsb` on the word's bit list. Every large bound in types is a literal token (`16384n`), and generic lemmas over `Nat.pow2(w)` are bridged to it only by `Bool` evaluations: a closed `Nat` expression that evaluates to a few thousand crashes the checker when it lands in a type (upstream draft 03).
- Ticket 13: the generator is three emitters over `ngap_model.py` (the only module that reads pycrate's internals): `gen.py` writes `types.bend` (datatype, `read`, `write`, `after`, `valid` per type, tiers M and R of the message set) and `views.bend`, `gen_proofs.py` writes `laws.bend` and `proofs.bend`, `gen_show.py` writes `show.bend`. The views live in `kernel/ngap/gen/views.bend` rather than `kernel/ngap/view.bend` because they are derived from the object sets like the codec; the hand-written part (IE, containers, PDU header, the view prelude) is `kernel/ngap/frame.bend`.
- Ticket 13: the 420 per-type laws are stated in `kernel/ngap/gen/laws.bend`, generated with the code, and `LAWS.bend` points there; `PROOF.bend` imports the generated proofs. `ngap.<T>.suffix` is canonical decoding: `T.read(Cur{rem, bits}) = Done{(v, Cur{rem2, bits2})}` gives `bits == T.write(v, rem, bits2)` and `rem2 == T.after(v, rem)`, the APER form of "the consumed prefix is exactly what the wire format declares" and stronger than "the rest is a suffix". It rests on canonical decoding of every primitive (`kernel/proofs/canon.bend`), which the ticket 12 codec was built for (minimal lengths and integers, zero padding, the extended form refused for values that fit the root).
- Ticket 13: a view takes the IEs of a message's object set as its known ids; it fails on a duplicate id, on an unknown IE with criticality reject, on a missing mandatory IE, and on a known IE whose value does not decode exactly (whatever its criticality); unknown IEs with criticality ignore or notify are skipped. An extension bit set on a SEQUENCE or CHOICE, and an ENUMERATED extension index of 64 or more, are `Unsupported`; iE-Extensions and unknown IEs stay raw open-type bytes. CONTAINING octet strings (the PDU session transfers) stay bytes in the carrying message; the transfer types are generated and decoded by the procedure that needs them.
- Ticket 13: the generated per-message helpers (`Ie.check`, `View.check`, `Message.show`) are picked by the (PDU kind, procedure code) pair NGAP-ELEMENTARY-PROCEDURES binds to each message, not by name: that is what a PDU carries, and the name dispatch overflowed `bend --verdict` (upstream draft 04). A CHOICE index is read as a `Size`-coded `Nat` (the same bits as the constrained integer), so the alternative dispatch matches a `Nat` directly, which the suffix proof needs.
- Ticket 13: the differential oracle compares a textual normal form of each captured PDU: pycrate's value tree against our decoding, with extension and unknown IEs compared as the octets pycrate re-encodes for them; it also requires pycrate to re-encode every captured PDU to the captured octets.
- Ticket 14: a PFCP message keeps its length word as read, like NAS, and `Msg.make` computes it; validity ties it to the SEID, sequence, spare and IE octets (`body_size`), so `header.length_consistent` is a corollary of the reader's spec. The flags octet must be exactly 0x20 or 0x21 (version 1, S clear or set, MP clear) or the message is `Unsupported`; the spare octet after the sequence number must be zero or it is `Invalid`; message type and IE type/length must fit their fields or they are `Invalid`, so what reads is what writes.
- Ticket 14: the SEID is kept as its 8 octets and the sequence number as a 24-bit U32; an IE is its type, length and raw body, typed views (`exact`) decode a body whole or fail, and grouped IE bodies are IE lists read with the same reader. An F-TEID is either a TEID with its addresses or a CH request, so the CH form cannot carry a TEID or an address by construction, and `Fteid.valid` is what the advisory asks: an address is named and each has its length. The UE IP choose and prefix forms and OHC VLAN tags are `Unsupported` since eUPF never sends them. `pfcp.suffix` and `pfcp.ie.suffix` assume `all_bytes` of the input, as the NAS suffix laws do.
- Ticket 15: PFCP information elements and the Config TLVs are one wire format (16-bit kind, 16-bit length, body), so one module `kernel/tlv.bend` and one proof set serve both; PFCP's IE laws keep their advisory names over it. A Config keeps its TLVs in wire order and a getter answers the last occurrence of a tag, so decoding is lossless and canonical (suffix holds), a repeated tag replaces the earlier one, and unknown tags are carried but never asked for; a known tag whose value has the wrong length, or a subscriber that does not parse, makes the Config `Invalid`.
- Ticket 15: length and count words (frame body, NgapData and PfcpData lengths, the Actions count, log text) are kept as read and tied to their content by `valid`, as in NAS and PFCP; `make` fills them. The event kind byte is compared in turn (`U32.is_eq`) rather than matched as a literal, because a literal match on a U32 leaves the fall-through branch stuck for the checker and the suffix proof needs the kind back from each branch. The log level is a four-valued type, not a ranged byte. The stream word is checked to fit 16 bits on read so that what reads is valid.
- Ticket 16: the state is one record (configuration, the NGAP associations that are up, UE contexts keyed by AMF-UE-NGAP-ID, PDU sessions keyed by local SEID, the PFCP sequence counter, the next AMF-UE-NGAP-ID and timer id, the PFCP recovery stamp); tables are U32-keyed association lists (`kernel/table.bend`), small enough for one gNB and proof-friendly, since Base's Map is keyed by strings. Config is typed once (`Cfg`) from the TLVs; a Config missing any of tags 0x0001 to 0x0012 is logged and ignored, so the kernel never runs half-configured. The PFCP Recovery Time Stamp is the first four octets of the Config event's entropy, a fresh value per start, since the kernel has no clock and eUPF only compares it for change.
- Ticket 16: an NGAP PDU that fails to decode (PDU, IE container) gets Error Indication with `transfer-syntax-error`; one whose view fails (duplicate id, unknown reject IE, missing or malformed mandatory IE) gets `abstract-syntax-error-reject`; a procedure this milestone does not handle yet gets `message-not-compatible-with-receiver-state`. NG Setup before Config is answered with NG Setup Failure, cause `unspecified`. Procedures are told apart by comparing kind and code in turn rather than by a literal match, for the same checker reason as the frame kind byte. NgapAssocDown drops the UE contexts the association owned, then the sessions whose UE is gone, sending a PFCP Session Deletion for each.
- Ticket 17: a UE context is created only once the InitialUEMessage's view passes and its NAS-PDU is a Registration Request that parses; anything else is answered with Error Indication and leaves the state alone (GHSA-cfp8-93x2-6h9x). Every phase before registration carries its guard timer: T3570 for identification and T3560 for authentication, 6 s, four retransmissions, then UE Context Release Command and the `Releasing` phase, which waits for the gNB's Complete under a guard of its own (ticket 33). After a successful authentication the guard keeps running until Security Mode (ticket 18) replaces it, so no context is ever unguarded.
- Ticket 17: the SQN is advanced by 32 before each vector and stored back; a synch failure whose AUTS authenticates (f1*, f5*) sets the subscriber's SQN to the UE's and re-authenticates once, a second one is rejected. No configuration, a SUCI that does not deconceal, an identity that is not a SUCI or 5G-GUTI, or an unknown subscriber all get Registration Reject #7 and release. UE-associated signalling from an association that does not own the UE, or with another RAN-UE-NGAP-ID, gets Error Indication (unknown-local-UE-NGAP-ID) and changes nothing. Plain NAS not expected in the UE's phase is logged and ignored. UE procedures return semantic actions rendered to frame actions at the boundary, so "emits no NG Setup Response" is one lemma over the action type, not a walk over every branch. NGAP messages are told apart by their first two octets in the laws (kind and procedure code), which is what the header carries.
- Ticket 18: every UE procedure answers with a transaction (`Tx`: put a context, forget one, replace the subscribers, consume an id or PFCP sequence numbers, or several in order) and semantic actions, and one interpreter applies it; the one write path (`Gmm.place`) puts the context and releases every live context it conflicts with (same SUPI, 5G-TMSI or RAN-UE-NGAP-ID on the association), Release Command and PFCP deletions included, so takeover is uniform and `amf.indexes.unique` is one lemma per transaction kind. The indexes are the contexts themselves, searched; the UE table's filters are one sieve (`Others`, `Clear`, `Victims`, `Except`), so "a sifting of a unique table is unique" is proven once.
- Ticket 18: the integrity algorithm is the first configured NIA the UE supports among those the kernel implements (NIA2; NIA0 is not representable), the ciphering algorithm the first configured NEA it supports (NEA0, NEA2); none in common gets Registration Reject #23 (UE security capabilities mismatch). The Security Mode Command replays the UE security capability, requests the IMEISV and RINMR, as the captured one does, and matches it byte for byte. Sessions of a released context are deleted at eUPF when the context is forgotten (Release Complete) or taken over; an owner's Release Complete forgets the context whatever its phase.
- Ticket 18: T3512 is encoded as five units of ten minutes (50 min), the closest GPRS Timer 3 value to the 54 minutes the ticket asks for, which TS 24.008 §10.5.7.4a cannot encode; the Registration Accept carries only what the ticket lists (result, 5G-GUTI, TAI list, Allowed NSSAI, T3512), and the Initial Context Setup Request only its mandatory IEs plus the NAS-PDU (no UE-AMBR before a PDU session). The NGAP security capability bit strings start at algorithm 1, so bit 1 of the NAS octet is dropped. On T3550 expiry the Registration Accept is retransmitted over DL NAS Transport, like the other guarded messages.
- Ticket 18: with a security context in force, only a message that verifies under it is read; one that does not is logged and ignored, and a verified message not expected in the phase still records its uplink COUNT, so it cannot be replayed. Re-registration arrives as a new InitialUEMessage, which creates a new context and evicts the old one: that is the re-authentication TS 24.501 §4.4.4.3 asks for. A UE Context Release Request from the owner is answered with a Release Command carrying its cause; from anyone else, Error Indication (`amf.ue_context_release.owner_only` covers Request and Complete as one law with two halves).
- Ticket 19: sessions follow the UE design: a session is an immutable identity (UE, PDU session identity, UE IPv4, uplink TEID) and a variable part (UP SEID, pending PFCP sequence number, phase), the indexes are the sessions themselves and the table's filters are one sieve, so `smf.ip_pool.unique` and `smf.teid.unique` are the UE proof again; a session put evicts the sessions it conflicts with (address, TEID, or the UE's PDU session identity), deleting them at eUPF, which is the takeover the spec asks for. The UE address is the first free host of the pool after the gateway (network, gateway and broadcast left out); the N3 TEID and the local SEID come from entropy (octets 20 to 23 and 24 to 27), never zero. The UE's NAS context moves on through a `Rephase` transaction that changes no identity, so the reject paths provably leave the sessions alone.
- Ticket 19: the N4 association is timer 0 (UE and session guards start at 1): T1 3 s, three tries, a 10 s pause, then again; once up, a Heartbeat Request every 30 s, and eUPF's heartbeats are answered. Session requests are not retransmitted (a duplicate Session Establishment creates a second session at eUPF); one 3 s guard bounds each PFCP wait and the gNB's setup. A request while the association is down gets #38. The Session Establishment Request carries two PDRs (uplink by N3 TEID with outer header removal, downlink by UE address), two FARs (uplink forward to core, downlink drop until the gNB's tunnel is known, then Update FAR to forward with outer header creation) and one QER (QFI 1, gates open, 1 Gbit/s each way), as docs/research/eupf-pfcp.md prescribes; URR, BAR, SDF filters and network instances are left out. eUPF's Session Deletion Response and Heartbeat Response are ignored.
- Ticket 19: the Config has no AMBR, so the session and UE aggregate maximum bit rates are 1 Gbit/s each way (the capture's). The transfer carries the AMBR, the N3 tunnel, IPv4 and QoS flow 1 (5QI 9, ARP 8, no pre-emption) and matches the captured one byte for byte; the Setup Request also carries the UE-AMBR. The Accept carries IPv4 and SSC mode 1, the default rule (QFI 1, precedence 255, one match-all filter), the Session-AMBR, the PDU address, the DNS server when the ePCO asked for it (container 0x000d) and #50 when IPv4v6 was asked for and IPv4 granted. 5GSM causes: #95 for a session identity outside 1 to 15, #31 for a request type other than initial and for a Modification Request, #27 for another DNN, #70 for another slice, #50 for a type other than IPv4 or IPv4v6, #26 for an exhausted pool and for a failure at the gNB, #38 for eUPF refusing, timing out or being unassociated. A later failure after the Accept (modification refused or unanswered) drops the session silently; a PDU Session Release Request from the UE is logged and ignored (not in the milestone).
- Ticket 19: the NGAP generator takes four optional IEs beyond its tiers (the PDU session setup results 75 and 58 the SMF reads, the aggregate bit rates 110 and 130 it sends); the generated views gained Criticality Diagnostics fields where that type is now in the closure. A constrained INTEGER is held as its offset from the lower bound in the generated code (ticket 12), so an ARP priority of 8 is written as 7.
- Ticket 20: the kernel process takes one edge and closes the listener; an undecodable event, bytes left over in its frame, an oversized frame or a socket error are protocol errors, so the connection closes and the process exits 1 without answering (the edge must not guess what was meant); the edge closing the connection ends the process with exit 0; a missing or unparsable port argument exits 2. Reads are 64 KiB at a time and frames are cut from the accumulated buffer, so one `recv` may carry several frames or part of one.
- Ticket 21: the edge is a library behind a thin binary. Socket threads (one accepting, one reading per association, one for N4) feed a channel, and the loop waits on it with the next timer deadline as the timeout, so `unsafe` stays in the SCTP module and there is no poll loop. The kernel's path and TCP port come from the TOML, no port handshake. Association ids count up from 1 and are never reused; after an NgapClose the edge does not report NgapAssocDown for that association, since the kernel asked for the close. Log actions are not printed again: the kernel's stderr is inherited. N4 datagrams are filtered by source address alone. `test-vectors/frames.json` is laid out by hand from the spec table, length word included, and both `kernel/tests/frame.bend` and the cargo tests read it; the in-code round-trip checks it made redundant were removed.
- Ticket 23: the audit found two laws short of their tickets and fixed them rather than listing them: `smf.establish.failure_releases` covered two of the four later failures (eUPF refusing the establishment, the guard expiring while creating) and now covers the guard in every pending phase, eUPF refusing the modification and the gNB reporting the session failed to set up, the last for a response that names the one session our requests carry; `ngap.no_big_nat` (ticket 13) had never been stated and is now the bound and byte range of AMF-UE-NGAP-ID and BitRate, which are byte lists by type. `aper.padding.zero` was renamed `aper.pack.padding_zero`, since a second law one character away from `aper.padding_zero` is a trap for readers. The clauses that remain arguments rather than laws are listed in `loop/acceptance-report.md`.

- Ticket 32: `amf.takeover.authenticated` assumes `Ues.unique` of the state before the step. Every state `step` reaches satisfies it (`amf.indexes.unique`); without it a gNB's own context could already share a SUPI or 5G-TMSI with another association's, which no reachable state allows. (decidido por el agente, revisable)
- Ticket 32: the law covers every context another association owns, not only registered ones. (decidido por el agente, revisable)
- Ticket 32: "holds a verified security context" means a NAS security context in the phase, from Security Mode on. Only `Gmm.secure` creates one, after HRES* and RES* verify. (decidido por el agente, revisable)
- Ticket 32: the 5G-TMSI is the first of four entropy words that no context holds. If all four are taken (probability (n/2³²)⁴) the new context is released, so no UE is ever evicted for a collision; before this change a collision evicted another gNB's UE and made the law false.
