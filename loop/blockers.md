# Blockers

One entry per blocker: ticket, what was tried, smallest reproduction, what would unblock it.

## Ticket 38, item 2: `state.ids.free` is false at id exhaustion (2026-11-07)

Items 1, 3 and 4 of ticket 38 are done (`amf.contexts.guarded`, `smf.sessions.known`, `smf.establish.failure_releases` restated, the report). Item 2 is not: the invariant does not hold in every reachable state, so it cannot be proven, and the two laws that would use it (`amf.takeover.authenticated` over the wrap case, `amf.guard.expires` over the one row a timer belongs to) stay as they are.

- **Counterexample.** A state with a context under every AMF-UE-NGAP-ID but `next_ue = n` (2³² − 1 contexts, each from its own RAN-UE-NGAP-ID). An InitialUEMessage runs `BumpUe` before the context is put: `Ues.free_key(2³², n + 1, ues)` passes every taken key and lands on `n`, which is still free, so `next_ue` stays `n`; then the context is put under `n`. The state after the step has `next_ue` live. Timers fail the same way once 2³² − 1 guards are live (`Timers.free` returns its last candidate unchecked when its fuel runs out). Nothing bounds the number of contexts or sessions, so both states are reachable.
- **What was tried.** Proving the search finds a free id needs pigeonhole over `U32.add` (the ids `id + 1 … id + n` are distinct for n < 2³²) on the bit-level `Word`, plus a counting lemma and a capacity the kernel enforces; the proof library has no `U32.add` lemmas. A free-by-check allocation (refuse when the bumped id is taken) makes the ids free by construction but the walk must then follow that the context put under `next_ue` is the one the bump moves past, which `Lv.free` cannot express without a parameter threaded through every 5GMM lemma, and timer allocation has six sites (five guard puts and session creation), one of them the release, which cannot be refused.
- **Smallest reproduction.** The counterexample above; no `.bend` test can build 2³² contexts.
- **What would unblock it.** A design choice for the owner:
  - **A (recommended).** Guard timers are the row's own key: a context's guard is its AMF-UE-NGAP-ID, a session's its local SEID, from a key space disjoint from the contexts' (for example the top bit set). `next_timer`, `BumpTimer`, `Timers.free` and `Timers.taken` go; "no two rows share a guard timer" follows from `amf.indexes.unique` and `smf.ip_pool.unique`. The edge already moves a timer started again (`edge/src/timers.rs`), so reusing an id cannot fire a stale guard. What is left to allocate is checked where it is chosen: the InitialUEMessage searches for an AMF-UE-NGAP-ID that no context holds and is refused when there is none, and session creation draws its SEID clear of the contexts' keys (ticket 35 already asks for redraws on collision). `next_ue` becomes where the search starts, so the law reads "the key an InitialUEMessage gives its context holds none" instead of "`next_ue` is free". This touches ticket 35 and changes the timer ids on the wire.
  - **B.** Keep the counters, cap contexts and sessions, and prove the search finds a free id below the cap (the `U32.add` lemmas above).
